# Как я написал веб-клон Anki для своей девушки: от реверса mediasrv до Rust ядра и Svelte 5

> **TL;DR:** За несколько месяцев мы создали **Cardly** — open-source веб-версию Anki, которая работает прямо в браузере, выглядит как современное приложение 2026 года, работает на официальном Rust-ядре Anki (`rslib`), поддерживает алгоритм FSRS, синхронизируется напрямую с AnkiDroid/AnkiMobile, запускается одной командой в Docker и умеет генерировать карточки по фото конспекта через ИИ.
>
> Исходный код: [github.com/ankitects/anki](https://github.com/ankitects/anki) (AGPL-3.0)  
> Живое демо: [cardly.app](https://cardly.app) (или локально `docker compose up -d`)

---

## 1. «Почему в 2026 году это до сих пор выглядит как Windows 98?»

Всё началось с банальной бытовой истории. Моя девушка учит несколько языков и готовится к международным сертификационным экзаменам. Она заядлый пользователь Anki: её коллекция насчитывает больше 35 000 карточек, а стрик непрерывных ежедневных повторений перевалил за 700 дней.

Каждый вечер повторялась одна и та же картина:
- Дома на ноутбуке всё прекрасно: мощный десктопный Anki, статистика, аддоны, шорткаты.
- Но стоит ей оказаться на парах в университете, на работе за чужим компьютером или в метро с планшетом — начинались мучения.

Официальный **AnkiWeb** — это потрясающий проект с точки зрения надежности инфраструктуры, за что Дэмиену Элмсу (Damien Elmes) низкий поклон. Но функционально веб-версия практически не менялась с конца 2000-х:
1. **Нет нормального менеджера карточек (Browser):** нельзя гибко искать по тегам, фильтровать поля, выделять пачки карточек, менять тип записи на лету.
2. **Нет настройки FSRS:** современный алгоритм интервального повторения Free Spaced Repetition Scheduler (FSRS) стал стандартом в десктопной версии, но веб-интерфейс не давал гибко управлять параметрами ретенции.
3. **Создание карточек:** ввод формул MathJax, форматирование cloze-удалений `{{c1::...}}` и медиафайлов превращался в ручную рутину.
4. **UX и дизайн:** полное отсутствие адаптивного мобильного PWA, плавных анимаций, горячих клавиш и тёмной темы, соответствующей системным дизайн-токенам.

В какой-то момент прозвучал прямой вопрос: *«Слушай, ты же программист. Неужели в опенсорсе нет нормального, красивого веб-клиента, в который можно просто зайти с любого браузера и учить свои карточки так же, как на десктопе?»*

Я пошёл гуглить и с удивлением обнаружил: **полноценного решения нет**. Были либо отдельные фронтенды с собственными проприетарными базами данных (теряющие совместимость с `.apkg` и AnkiWeb), либо устаревшие пет-проекты, заброшенные 5 лет назад.

Так начался проект **Cardly**.

## 2. Ловушка переписывания: почему нельзя просто взять и написать свой Anki на TypeScript

Первый порыв любого веб-разработчика: «Да что там делать? Таблица в SQLite, карточки с Question/Answer, алгоритм SM-2 из пяти строчек на JS, натянем Tailwind и готово за пару выходных!».

Это колоссальная ошибка, на которой споткнулись десятки энтузиастов. 

За 18+ лет развития Anki внутри накопилось огромное количество тонкостей:
- **Алгоритм FSRS v4/v5:** расчёт стабильности (stability), извлекаемости (retrievability) и сложности (difficulty) с векторной оптимизацией весов под конкретного пользователя.
- **Движок Cloze:** вложенные пропуски, подсказки `{{c1::скрытый текст::подсказка}}`, динамическая генерация N виртуальных карточек из одной заметки.
- **MathJax 3 и LaTeX:** клиентский рендеринг формул с поддержкой `\begin{align*}`, химических формул mhchem и кастомных макросов.
- **Шедулер v3 (23.10+):** интервалы шагов обучения, авто-суспенд личей (leeches), перемешивание колод и лимиты новых карточек на день.
- **Транзакционная целостность:** транзакции базы данных SQLite, синхронизационный журнал USN (Update Sequence Number), слияние схем при импорте.

Переписать это с нуля в вебе и не сломать совместимость с миллионами существующих колод — практически невозможно.

### Архитектурный инсайт: используем оригинальное ядро `rslib`

Несколько лет назад команда Anki совершила масштабный подвиг: переписала всю вычислительную логику, работу с SQLite и алгоритмы интервального повторения с Python на **Rust** (библиотека `rslib`). 

Десктопное приложение Anki на PyQt устроено так:
- GUI на Python/Qt запускает Rust-бэкенд.
- Общение между интерфейсом и ядром происходит через строго типизированные сообщения **Protocol Buffers (Protobuf)**.
- Веб-компоненты ревьюера и настроек общаются с локальным HTTP-сервером через `POST /_anki/{method}`.

**Наша идея была простой и дерзкой:**
Зачем пытаться эмулировать логику Anki, если мы можем скомпилировать официальное Rust-ядро `rslib` напрямую в единый нативный бинарник, поднять над ним легковесный асинхронный HTTP/WebSocket сервер на **Axum (Rust)**, сгенерировать TypeScript-биндинги из оригинальных `.proto` файлов и написать современную SPA-оболочку на **Svelte 5**?

Никакого дублирования логики. Прямая совместимость с оригинальным Anki через официальное ядро rslib на уровне байтов.

```
┌────────────────────────────────────────────────────────┐
│                   Cardly Architecture                  │
└────────────────────────────────────────────────────────┘

  [ Web Client / PWA: Svelte 5 + Runes + TypeScript ]
                          │
                   (HTTP/JSON & Protobuf)
                          │
  ┌───────────────────────▼────────────────────────────┐
  │         Cardly Server (Rust + Axum)                │
  │                                                    │
  │  ├─ Multi-User Auth & Isolated SQLite Collections  │
  │  ├─ Upstream Protobuf RPC Dispatcher               │
  │  ├─ Built-in Sync Server (/sync/* & /msync/*)      │
  │  ├─ Sandboxed Media & Card Rendering Proxy         │
  │  └─ AI Card Generation Engine (Gemini / OpenAI)    │
  └───────────────────────┬────────────────────────────┘
                          │
         (In-process Direct Memory Linking)
                          │
  ┌───────────────────────▼────────────────────────────┐
  │     Official Anki Rust Core (`anki/rslib`)         │
  │                                                    │
  │  ├─ FSRS v4/v5 Scheduler & SM-2 Engine             │
  │  ├─ SQLite DB Storage & Transactions               │
  │  ├─ Cloze Parser & MathJax Rendering Engine        │
  │  └─ Multi-level Undo / Redo Manager                │
  └────────────────────────────────────────────────────┘
```

## 3. Технические челленджи

### Челлендж 1: Проброс Protobuf RPC в веб без бойлерплейта

В оригинальном Anki определено более 80 сервисных методов Protobuf (`AddNote`, `SearchNotes`, `AnswerCard`, `GetDeckNames`, `UpdateNotetype` и т.д.).

Мы не стали писать ручные контроллеры для каждого эндпоинта. Вместо этого:
1. Во время сборки утилита `ninja ts:sveltekit` генерирует готовые TypeScript-классы сообщений через `@bufbuild/protobuf`.
2. На стороне Rust Axum-хэндлер `/_anki/{method}` принимает бинарный `application/binary` payload, по названию метода через макросы рефлексии сопоставляет сигнатуру сервиса в `rslib`, исполняет её в пуле `tokio::task::spawn_blocking` и возвращает результат клиенту.
3. Время отклика интерфейса на локальной машине или VPS составляет **0.8 – 2.5 миллисекунды**.

### Челлендж 2: Песочница карточек и CSP

Карточки Anki создаются миллионами людей. Пользовательские колоды могут содержать сложнейшие скрипты (например, интерактивные викторины, анимации иероглифов, кастомные канвасы). При этом в веб-приложении мы обязаны соблюдать жесткую безопасность: вредоносный JS из скачанной колоды не должен иметь возможности украсть JWT-токены или отправить запросы от имени пользователя.

Мы решили эту проблему двухконтурной изоляцией:
- Рендерер карточек упакован в изолированный `<iframe>` с атрибутами `sandbox="allow-scripts"`.
- Заголовки Content Security Policy запрещают выполнение скриптов в родительском окне.
- Запросы за картинками и звуками идут через `/media/{filename}`, где проверяются права доступа пользователя и отдаются строгие заголовки `Cross-Origin-Resource-Policy: same-origin` и `Cache-Control`.

### Челлендж 3: Виртуализированный менеджер колод на Svelte 5

Менеджер карточек (Browser) в Anki должен мгновенно отображать десятки тысяч строк. Попробуйте отрендерить 40 000 DOM-узлов в React — браузер немедленно замрёт на несколько секунд.

Мы написали Browser на новом **Svelte 5 с рунами** (`$state`, `$derived`, `$effect`):
- **Оконная виртуализация (Windowed Virtual Scrolling):** в DOM одновременно существует ровно столько строк, сколько помещается на экране (+ небольшой буфер).
- **Сверхбыстрый скролл 60 FPS** даже на старых смартфонах.
- Полноценная поддержка мульти-селекта (Shift+Click, Ctrl+A), контекстных меню, массового добавления тегов и поиска с синтаксисом Anki (`tag:biology is:due rated:3:1`).

### Челлендж 4: Встроенный сервер синхронизации для AnkiDroid и AnkiMobile

Это была главная мечта: чтобы приложение не было «вещью в себе».

Мы реализовали полную поддержку официального протокола синхронизации Anki (эндпоинты `/sync/*` и `/msync/*`):
- Карточки, колоды, история повторений и медиафайлы синхронизируются по нативному протоколу Anki сжатыми чанками.
- **Прямая поддержка AnkiDroid (Android) и AnkiMobile (iOS):** достаточно зайти в настройки официального мобильного приложения, выбрать «Пользовательский сервер синхронизации» и ввести адрес своего сервера `https://my-cardly.org/sync/`.
- Всё синхронизируется на лету: поучил карточки в метро на телефоне через AnkiDroid -> пришёл домой, открыл браузер на компьютере — все интервалы уже актуальны.

## 4. Киллер-фича: Мультимодальный ИИ-генератор карточек

Когда базовая функциональность Anki была отполирована до идеала, девушка сказала: *«Учить готовые карточки — кайф. Но когда профессор на лекции даёт 40 страниц новой темы или присылает фото доски с формулами, я трачу 3 часа только на то, чтобы набить карточки вручную. Можно сделать так, чтобы карточки собирались сами?»*.

Так в Cardly появился встроенный **AI Card Generator**:

```
 [ Фото конспекта / Слайд / PDF ]
                 │
                 ▼
 [ Мультимодальный LLM (Gemini / OpenAI / Ollama) ]
                 │
   (Minimum Information Principle + Cloze Prompting)
                 │
                 ▼
 [ Интерактивный предпросмотр и редактирование ]
                 │
                 ▼
 [ Пакетное добавление в коллекцию Anki в 1 клик (с поддержкой Undo) ]
```

### Как это устроено под капотом:

1. **Мультимодальный ввод:**
   - Поддерживается как вставка текста/конспектов, так и прямая загрузка фотографий (OCR рукописных конспектов, диаграмм, таблиц учебника).
2. **Промпт-инжиниринг на основе Minimum Information Principle:**
   - Большинство обычных промптов для ChatGPT создают ужасные карточки: громоздкие абзацы текста, вопросы с тремя подпунктами или бесполезную викторинную мишуру.
   - Мы зашили в системный промпт строгие правила мнемоники: одна карточка — один атомарный факт; четкий лаконичный ответ; автоматическое создание cloze-удалений `{{c1::...}}` на ключевые термины; генерация аккуратных тегов.
3. **Любые провайдеры по выбору пользователя:**
   - **Google Gemini** (включая бесплатные тарифы Gemini 1.5/2.0 Flash с огромным контекстным окном).
   - **OpenAI / OpenRouter / Groq** (GPT-4o, Claude 3.5, Llama 3).
   - **Локальные модели через Ollama** — для тех, кто заботится о полной приватности и не хочет отправлять свои конспекты в облако.
4. **Безопасное добавление с поддержкой Undo:**
   - Сгенерированные карточки не валятся в базу вслепую: открывается удобная таблица предпросмотра, где можно отредактировать формулировку, снять галочки с ненужных карточек и поправить теги.
   - При нажатии «Добавить» бэкенд регистрирует операцию в менеджере истории Anki (`addCustomUndoEntry`). Если вы случайно добавили не ту партию — достаточно нажать `Ctrl+Z`, и вся пачка мгновенно откатится назад.

## 5. Как развернуть у себя за 2 минуты

Для Cardly подготовлен полностью готовый Docker-образ. Вам понадобится любой копеечный VPS (от $4–5/мес, например, Hetzner, DigitalOcean или Timeweb Cloud) или домашний сервер с Docker Compose.

### Быстрый старт:

Создайте `docker-compose.yml`:

```yaml
services:
  cardly:
    image: ghcr.io/ankitects/anki:latest  # или локальная сборка
    container_name: cardly
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      CARDLY_HOST: "0.0.0.0"
      CARDLY_PORT: "8080"
      CARDLY_USER1: "alice:securepassword123"
      SYNC_USER1: "alice:securepassword123"
    volumes:
      - cardly_data:/data

volumes:
  cardly_data:
```

Запустите:

```bash
docker compose up -d
```

Откройте в браузере `http://localhost:8080` (или настройте HTTPS через Caddy/Nginx по нашему гайду в `docs/DEPLOY.md`).

Для теста доступен также интерактивный **Demo-режим** (`CARDLY_DEMO_MODE=true`), где можно протестировать приложение с предустановленными демонстрационными колодами (языки, география, наука с формулами MathJax), который автоматически очищается каждый час.
